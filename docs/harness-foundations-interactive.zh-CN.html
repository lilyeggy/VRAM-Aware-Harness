运行事实层

AgentRun

一次用户任务在 Harness 里的执行实体。它不是 Agent，也不负责调用模型；它负责记录“这次任务现在处于什么状态”。

本质

业务执行记录，也就是可持久化的任务实例。

为什么需要

PiAdapter 只能让 Pi 跑起来；AgentRun 让 Harness 知道任务是否排队、运行、失败、完成或等待恢复。

没有它会怎样

进程重启后只剩下 Pi 的会话历史，但 Harness 不知道业务任务是否完成、属于哪个 Tenant、是否应该恢复。

代码落点

`src/runs/agent-run.ts`，后续会有 `RunStore` 和 `RunService`。

面试一句话

AgentRun 是 Harness 对一次任务执行的事实建模，Runtime 只是它的执行后端。

最容易混淆的工程边界

AgentRun 和 Pi AgentSession 有什么区别？

AgentRun 是 Harness 的任务执行记录；Pi AgentSession 是 Pi 用来保存对话历史和内部上下文的运行时会话。

为什么既保存状态，又保存事件？

状态方便快速查询当前结果；事件解释状态为什么变成这样，并支持审计、恢复和调试。

为什么 Fake Runtime 还有价值？

它让 RunService、队列、恢复、事件持久化可以被稳定测试，不依赖真实模型、GPU 或 Pi 的不确定输出。
