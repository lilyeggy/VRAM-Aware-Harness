虚拟机到底是什么？
从 CPU 开始，一层一层拆

虚拟机 = 用软件造出来的"假电脑"，里面还能再跑一个完整的操作系统。要理解它，只需要知道四层东西，以及它们怎么配合。下面这张图就是全部的骨架，点击任意一层跳到对应章节。

第 4 层 · 客户机（虚拟机里的系统）一个完整的操作系统，以为自己在独占一台真电脑第 4、5 章 → 第 3 层 · 虚拟机监视器 VMM（Firecracker）宿主上的一个普通进程，负责"造假硬件"第 5、6 章 → 第 2 层 · 内核模块（KVM）Linux 内核里的一块，把 CPU 的虚拟化能力开放出来第 3、6 章 → 第 1 层 · 硬件（CPU + 内存）CPU 自带"虚拟化模式"，这是一切的基础第 1、2 章 →

第二部分

回到本项目：这些零件在哪里出现

底层原理讲完，再看我们的代码是怎么把它们拼起来的。

底层概念本项目中的对应代码位置
硬件虚拟化（VT-x）通过 /dev/kvm 访问，启动前先检查可读写firecracker-sandbox-driver.ts · accessSync(kvmPath)
VMM（虚拟机监视器）每台 VM 一个 Firecracker 进程，由 jailer 启动firecracker-sandbox-driver.ts · spawn(jailerPath, …)
模拟的串口内核参数 console=ttyS0，串口只留给内核日志驱动里的 boot_args
没有 PCI 总线内核参数 pci=off，Firecracker 的设备不走 PCI同上 boot_args
virtio 块设备系统盘 /dev/vda、工作区盘 /dev/vdb，guest 内挂到 /workspacePUT /drives/*，build-guest-rootfs.sh
virtio-vsock（宿主↔虚拟机通信）宿主连 vsock.sock，guest 里 socat 监听端口 5000firecracker-vsock-bridge.ts、inittab
客户机内存 = 宿主进程内存快照把这块内存整块写成 mem.snapvm-snapshot-manager.ts
