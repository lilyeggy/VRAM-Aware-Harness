系统设计题实战工坊

二面三面的主菜："设计一个多租户 Agent 平台 / 设计一个 LLM Gateway"。知识装进脑子之后，这一页练输出。

万能四步法：45 分钟时间盒

系统设计题没有标准答案，但有标准节奏。四步走完，每步都有时间盒：

1
需求澄清（5 分钟）

功能需求圈边界（哪些不做！）、非功能定指标（QPS/延迟/可用性/隔离等级）。主动问"租户规模多大？任务平均时长？"——提问质量就是资深度。

2
容量估算（5 分钟）

并发任务数 × 平均 token 用量 → GPU 张数；排队长度 → 队列存储；日志量 → 事件库选型。数字可以粗，但要有估算意识。

3
分层架构（15 分钟）

入口 → 身份 → 编排 → 执行 → 基础设施五层画图，每层说清"负责什么/不负责什么"。边界意识比组件堆砌值钱。

4
深挖权衡（15 分钟）

面试官必钻：故障恢复、公平性、隔离、成本。每个点给"方案 A vs B + 我选哪个为什么"。承认取舍比假装完美高级。

真题② 设计一个 LLM Gateway（Shopee 二面原题 · 对照打分）

用 Shopee 的评分点给你的 C 方向实现逐项打分——✅ 已实现 ⚠️ 部分 ❌ 未做，把差距讲成 roadmap：

评分点你的现状面试话术
基于能力的路由✅ 逻辑模型 → 后端映射（candidatesFor）"我实现了主备顺序路由 + 熔断过滤 + OpenAI 兼容透传含 SSE 流式；下一步按这份评分表扩展——优先做决策持久化和跨模型降级，因为它们直接服务成本治理"
成本/延迟路由❌ 未做（RouteDecision 已记录延迟可作依据）
语义路由❌ 未做
Fallback 四级✅ 同模型主备回退 ⚠️ 缺跨模型降级与兜底模型
负载均衡⚠️ 配置顺序即优先级，无加权/token 吞吐均衡"LLM 请求时长方差极大，token 吞吐均衡比轮询合理——我的 metrics 解析已能产出吞吐数据"
熔断器✅ 连续 3 失败开断、30s 冷却半开经典三态机完整落地
统一协议适配✅ OpenAI 兼容 + SSE 流式透传 + 模型名替换
语义缓存❌ 未做"需要 Embedding 相似度匹配，且要回答缓存命中时 KV Cache 前缀共享的关系——我知道坑在哪所以排在后面"
可观测性⚠️ RouteDecision 内存环形缓冲 200 条未持久化诚实边界第一句，然后给持久化方案
开源参照LiteLLM（统一代理）/ RouteLLM（模型路由研究）/ Portkey（网关 SaaS）——知道名字和定位即可
🥊
打分卡的用法

先自己打分再让面试官看，主动权就在你手里："这九个评分点我完成四个半，剩余的我都清楚为什么排后以及怎么做。"——把未完成从减分项变成规划能力的展示位。

附：沙箱类设计题要点（云端 Agent 沙箱）

2026 年的高频新题："设计一个云端大规模 Agent 沙箱系统"。四个必答要点：

会话粘性 vs 冷启动Sticky 会话保上下文但绑定节点易热点；无粘性要解决状态外化——你的 Checkpoint+DB 重建正是后者
持久化卷workspace 生命周期长于容器：独立存储挂载（你的 bind mount 方案）或对象存储快照
弹性伸缩预热池（秒级领取）vs 冷启动（镜像拉取秒级开销）；runsc 1.22x 开销是量化依据
资源配额CPU/内存/PID/网络四限 + 磁盘配额的诚实说明（bind mount 做不到磁盘限额你会拒绝执行）
