项目定位与全局图景

面试的前 30 秒决定后面 30 分钟聊什么——这一模块给你那 30 秒，以及它背后的整张地图。

面试官问：「介绍一下你的项目」

答错层次，是面试里最贵的错误：把它说成「又一个 Agent 应用」，后面的所有深挖都会失去支点。这个项目的准确定位是——Agent 之外的控制面服务。下面两段话请原样背下来。

一句话定位 · 必须原文背下

VRAM-Aware Agent Harness 是一个支持团队共享本地大模型的多租户 Agent 任务服务。用户在独立 Workspace 中提交任务、观察 Agent 执行并获得最终回答、文件 Diff 和 Artifact；系统负责可信租户身份、隔离运行环境、公平调度共享 GPU、工具权限与副作用治理，以及故障后的安全恢复。

30 秒电梯稿 · 面试开场用

我做了一个多租户 Agent 任务控制面。Agent 负责「动脑」，我的系统负责「安排与安保」：多租户身份、GPU 资源准入与背压、runsc 沙箱隔离、工具副作用记账与崩溃恢复，以及执行评测、观测驾驶舱和 LLM 路由网关三个深化方向。254 个测试全绿，并在 T4 GPU 上做了 120 并发的真机验证。

电梯稿里每个数字都要能展开讲。这是你的证据链：

254 tests / 0 fail全量测试绿，说明控制面的状态机与恢复逻辑被反复锤过
9 项沙箱攻击真机 PASS逃逸类攻击在 runsc 沙箱里全部被拦住，隔离不是纸面声明
T4 · 120 并发 → CRITICAL → QUEUE真机上把 GPU 压到临界态，系统自动从放行切换为排队
runc vs runsc 冷启动 1.22x为隔离付出的启动代价只有 22%，可接受且有数据支撑
15 个 schema migration控制面数据模型随设计迭代演进了 15 版
8 个 HTTP 端点对外接口收敛克制，控制面不贪多

一个隐喻定调：物业公司与房客

Agent（Pi）是房客——会自己做饭、洗澡、接待客人，对应思考、调模型、用工具。Harness 是物业公司——决定谁能进楼、哪间房给谁用、水电超载要限流、出了事故怎么善后。

物业不替房客过日子；但没有物业的楼，是危楼。

🧠

房客 = Pi（行为平面）

自己决定做什么：推理、选择工具、组织回答。项目复用 Pi SDK，不重新实现「模型—工具循环」——动脑的事归它。

🏢

物业 = Harness（控制平面）

身份、策略、调度、隔离、记账、恢复。它不替模型做任何决策，但在副作用发生前握有最终否决权——安排与安保的事归它。

💡
关键洞察：否决权放在哪里

控制面不替模型做工具选择，但必须在副作用发生之前有最终否决权。事后审查无法撤销一次已经发出去的网络请求或已经删掉的文件——所以检查点必须在行动之前，而不是之后。

四个系统难题：整个项目的骨架

面试官接下来问的每一个深问题，几乎都落在这四张卡上。记住它们，你就有了整场面试的主线。

🧾

① 副作用感知的执行与恢复

工具是对外部世界的真实改变。动手前先记账（PREPARED → SUCCEEDED 双复写），崩溃后只重放安全副作用。→ Module 3

🚦

② 资源感知的准入与背压

读 vLLM /metrics + GPU 状态，分类 NORMAL/BUSY/CRITICAL/UNKNOWN，START/QUEUE 决策落库。观测失败 = QUEUE（fail-closed）。→ Module 4

🛂

③ 工具治理

每次工具调用都要过权限、超时、副作用分类、可重放性判断——工具不是自由变量，是被管制的边境口岸。→ Module 3 / 7

🔎

④ 可解释决策

模型调用、工具执行、资源快照、策略版本、理由、usage 全部落库，事后能回放出每一个「为什么」。→ 贯穿全部模块

技术栈五件套：每一件都有理由

B
Bun + TypeScript

单机控制面要的是快速启动与一流 TS 体验；类型系统就是状态机的第一道编译期防线。

P
Pi SDK 0.80.10

通过依赖倒置接口 AgentRuntime 接入——控制面依赖抽象而非具体实现，换 Runtime 不动地基。

G
runsc / gVisor

用户态内核拦截系统调用，多租户场景下容器隔离不够、虚机太重，它是那个刚好的中间点。

V
自托管 vLLM（OpenAI 兼容）

既要共享 GPU 的吞吐，又要 /metrics 观测口——OpenAI 兼容协议让接入零成本。

S
SQLite

单机控制面的状态、事件、审计全在一个库：同事务写入天然一致，备份就是一个文件。
