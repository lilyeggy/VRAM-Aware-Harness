八股速答：每题 60 秒版 + 项目桥接

1️⃣
Function Calling vs RAG，什么时候用哪个？

实时数据/执行动作 → FC；私有知识/离线文档 → RAG；实际系统常组合。桥接："我的项目是 FC 的安全壳——工具调用全部过策略守卫、副作用分类和沙箱命令边界，这是生产级 FC 和 demo 级 FC 的差别。"

2️⃣
幻觉怎么产生？怎么减轻？

模型在预测下一个 token 不是检索事实，天然会编。五板斧：RAG 供事实 / FC 查真实数据 / Structured Output 收窄格式 / Prompt 明示"不知道就说" / 多轮自检或交叉验证。桥接："工程侧我再加两板斧：副作用 fail-closed（不确定就不动手）+ 全量审计可回放——幻觉最多导致答错，不会导致做错。"

3️⃣
Structured Output 怎么保证稳定？

Prompt 规定格式不稳定；JSON Schema 约束（主流 API 支持）把字段名、类型、必填卡死。桥接："下游要自动化解析所以格式即契约——我的 RunEvent payload 带 payloadVersion 字段，就是给事件 schema 的演进留的版本位。"

4️⃣
上下文腐化 / Lost in the Middle 是什么？

窗口塞满后早期内容被稀释、注意力大幅下降；中间位置的信息最容易被忽略。桥接："所以工程上不是拼命塞满窗口而是精准控制放什么——我的方案是把记忆压缩整个交给 Pi 会话层（appendCompaction 写进会话文件持久化），Harness 只管选会话和复用句柄。"

5️⃣
RAG 检索策略怎么设计？

混合检索（向量抓语义 + 关键词抓精确）用 RRF 融合；Chunk 512-1024 token 带 50-100 重叠；HyDE 先生成假设文档再检索；重排序提升精度。桥接："我的项目没做 RAG——诚实承认，但我知道难点三座山：文档预处理质量、召回质量、生成忠实度。"

6️⃣
SFT vs RLHF？微调 vs RAG？

改行为风格用 SFT 快速迭代；对齐偏好用 RLHF/DPO；知识频繁更新用 RAG（改库不改模）；能力本质缺失才微调。桥接："我把模型当可替换工作负载（ADR 0005），这些是模型侧手段——我的立身之本是控制面语义不随模型升级漂移。"

7️⃣
多 Agent 主子通信链路怎么设计？异常怎么处理？

主 Agent 拆解任务 → 子 Agent 独立上下文执行 → 结构化结果回传；异常要有超时/重试/降级和部分结果回收。桥接："我的项目单 Runtime 但机制同构：Attempt 隔离每次执行、Sandbox LOST 事件 → Attempt INTERRUPTED → agent_interrupted 事件 → 调度层重新排队，这就是'子任务失败的标准化收敛路径'。"

8️⃣
Agent 成本失控监控什么指标？

token 总量与增速、单任务成本分布、cache 命中率、工具调用的间接成本（失败重试放大器）、预算告警。桥接："我的 Eval 层直接产出这些：totalTokens/costTotal/cacheHitRate 从 MODEL_COMPLETED usage 聚合，零新增采集。"
