Harness Engineering 话语映射

"你怎么理解 Harness Engineering？"——2026 年让候选人当场愣住的新题。这一页把你的项目翻译成面试官的业界语言。

先接住概念：出处与等式

被问"Harness 是什么"，60 秒标准答案分三段：定义 → 出处 → 等式。

1
定义：给 AI 装缰绳的工程学科

Harness 直译"马具"。模型是马，力量大但会脱缰；Harness 是让这股力量为你所用、跑偏能拉回、摔了能爬起来的那整套东西。

2
出处：两条权威脉络

Mitchell Hashimoto（HashiCorp 创始人）2026-02 博客《My AI Adoption Journey》提出 "Engineer the Harness"：每次 Agent 犯错就把修复沉淀进环境，让它结构性地不再犯。一周后 OpenAI 发文《Harness engineering》背书。

3
等式：Agent = Model + Harness

除模型外，决定它能否稳定交付的一切都属于 Harness。反推 Harness = Agent − Model——边界清晰。

三次重心转移：Prompt → Context → Harness

面试官追问"和 Prompt Engineering 什么区别"时的框架答案：

1

Prompt Engineering
让模型"听懂"——解决意图表达：角色/示例/CoT 把概率分布聚拢。止步于单轮。

→
2

Context Engineering
让模型"知道"——解决信息供给：召回/压缩/组装，对抗上下文腐化。止步于输入侧。

→
3

Harness Engineering
让模型"做对"——链路一长就会跑偏：谁来监督？谁拉回来？摔了谁扶？这是行动侧+校验侧的系统工程。

🎯
转折点话术

"前两代优化的是'怎么让模型更会想'，Harness 解决的是'怎么让它不跑偏、跑得稳、出了错还能爬起来'。"——这句说完再接下一屏的六层映射，面试官就知道你不是背名词的。

主视觉：业界六层 ↔ 本项目逐层映射

"如果让你设计一个 Harness，里面装什么？"——标准答案是六层组件。每一层你都有真实实现，这就是这张表的杀伤力：

业界六层 解决的核心问题 本项目的真实对应物
① 上下文精细化 这一轮该看到什么？ Pi 会话句柄设计：压缩与上下文归 Pi（SessionManager.appendCompaction 写进会话文件），Harness 只做"选会话+复用句柄+转事件"，不碰消息内容
② 工具系统 用什么动手？ ToolGateway：策略守卫前置 → PREPARED 记账 → 授权 → 执行 → SUCCEEDED+Checkpoint 同事务；工具经 runsc 容器命令边界执行
③ 执行编排 下一步该干啥？ Loop 归 Pi（ReAct 循环），编排归 Harness：Run 状态机 + 公平队列 + 资源准入 + single-flight drain——"循环之上"的受控执行
④ 记忆与状态 跨轮记住什么？ 状态全部外化：agent_runs 快照 + run_events 追加时间线 + Checkpoint 稳定引用（runtimeSessionRef+lastEventSequence），重启后从 DB 事实重建内存
⑤ 评估观测 做得好不好？ Eval 聚合器（零新增采集）+ /observe 驾驶舱 + policy_decisions 决策台账 + MODEL_COMPLETED usage 全落库
⑥ 约束恢复 出错了能不能爬起来？ fail-closed 四条线（观测失败→QUEUE / 副作用未知→人工 / 能力缺失→REJECTED / runtime 证据不符→删容器）+ RecoveryService 三件套
🗡️
差异化反杀话术

"业界的六层大多停留在方法论和最佳实践；我把其中最难的第六层'约束与恢复'做成了带数据库 CHECK 约束、乐观锁和真机攻击测试的系统。方法论我有体系，落地我有 schema 和 254 个测试。"

Mitchell 复利效应 ↔ 你的演进史

"每次 Agent 犯错，把修复沉到环境里"——你的项目就是这个哲学的实践样本，举两个真实证据：

🧱
修复沉到 schema：migration v4 的 CHECK 约束

踩过"资源观测失败时伪造快照"的坑之后，修复不是加一行 if，而是数据库 CHECK 约束：决策为 QUEUE+UNKNOWN 时快照必须为 null 且带失败原因——应用层忘了写，存储层也会拒绝。

✂️
修复沉到数据契约：migration v15 删 subject_id

发现 RequestPrincipal 里 subjectId 与 tenantId 一一对应纯属冗余后，直接 migration 删列——身份模型越简单，防串面越小。错误修在类型系统里，不靠人记。

📜
修复沉到测试：Fake Runtime 合同测试先行

AgentRuntime 接口的 start/resume/interrupt/unsubscribe/runId 隔离五条合同先于 PiAdapter 实现存在——任何未来 Runtime 想接入，先过同一套合同。

🔭
