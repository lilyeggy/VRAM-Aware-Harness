五层策略交集与 runsc 沙箱

策略不是 if-else 散落各处，而是：数据（五层）→ 纯函数（交集）→ 不可变快照 → 编译目标（OCI argv），每一步可测试可审计。

出国签证的联审模型

你能不能入境，不是某一关说了算——护照签发国（PLATFORM）、目的地移民局（TENANT）、航司规定（TEMPLATE）、入境卡（WORKSPACE）、本次行程（RUN）五方条件取交集：任何一方说不行，你就是不行。交集结果当场盖章封存（不可变快照），边检（沙箱）只认章不认人。

交集运算的四条规则

布尔权限 AND；列表取交集；资源上限取 min；workspaceRoots 按路径包含关系收窄。sandboxProfile 冲突直接抛错——不允许含糊地带病运行。computeEffectivePolicy 还会先校验五层缺一不可。

交集算法源码

CODE · src/policies/effective-policy.ts 
function intersectConstraints(
    left: PolicyConstraints,
    right: PolicyConstraints,
): PolicyConstraints {
    return {
        sandboxProfile: intersectSandboxProfiles(
            left.sandboxProfile ?? null,
            right.sandboxProfile ?? null,
        ),
        allowedTools: intersectValues(left.allowedTools, right.allowedTools),
        allowedSkills: intersectValues(left.allowedSkills, right.allowedSkills),
        allowedModels: intersectValues(left.allowedModels, right.allowedModels),
        workspaceRoots: intersectRoots(left.workspaceRoots, right.workspaceRoots),
        allowNetwork: left.allowNetwork && right.allowNetwork,
        allowProcess: left.allowProcess && right.allowProcess,
        allowedSecrets: intersectValues(left.allowedSecrets, right.allowedSecrets),
        resourceLimits: {
            cpuCores: minimum(left.resourceLimits.cpuCores, right.resourceLimits.cpuCores),
            memoryMiB: minimum(left.resourceLimits.memoryMiB, right.resourceLimits.memoryMiB),
            diskMiB: minimum(left.resourceLimits.diskMiB, right.resourceLimits.diskMiB),
        },
    };
}
白话翻译

两层约束进来，一层更严的约束出去——这就是"有效策略"的全部秘密。

沙箱等级特殊：两边都声明但不一样时直接抛错，因为"到底用哪个隔离级别"没有交集可言。

工具/技能/模型/Secret 白名单取交集——双方都点头的才保留。

路径根按包含关系收窄成更小的集合。

联网、开进程是布尔 AND——任何一方禁止即禁止。

CPU/内存/磁盘上限取更小的那个值。

从策略到 docker 命令行：OCI 编译产物

OciSandboxSpecCompiler 把 EffectivePolicySnapshot 编译成真实的 docker run 参数。先看前置守卫，再看产物：

CODE · src/sandbox/oci-sandbox-spec.ts · compile 
// 前置守卫（节选）：
if (policy.resourceLimits.diskMiB !== null) {

}
if (profile === "restricted-egress" && policy.allowNetwork) {

白话翻译

守卫一：bind mount 做不到磁盘配额——有这个要求就拒绝执行，而不是假装配了。

守卫二：受限出网 profile 还没接 egress 代理时，允许联网的策略直接拒绝。

下面开始编译真实命令行——每一面旗子对应一条安全承诺。

--user 65532:65532非 root UID 运行——容器内进程对宿主没有任何 root 权限
--read-only只读 RootFS——镜像层不可篡改，写入只允许 /workspace 和受限 tmpfs
--cap-drop ALL丢弃全部 Linux capabilities——连 chown 这类基础特权都没有
no-new-privileges禁止通过 setuid 提权——即使镜像里有 SUID 程序也升不了权限
--pids-limit 128进程数上限——fork 炸弹在 128 个进程处撞墙
--mount type=bind只挂载本 Attempt 的 workspace 目录——B 租户的文件物理上不在视野里
--tmpfs noexec,nosuid,64m临时目录可写但不可执行、不带 suid、最多 64MB
--network none默认无网络——非 development profile 强制 none

Secret 的短暂人生：标记替换 + 输出脱敏

Secret 值的一生只有一瞬间：argv 组装那一刻。它永不进入不可变 spec、永不进入 runtime evidence、错误输出还要过正则脱敏：

CODE · src/sandbox/oci-sandbox-spec.ts + container-sandbox-provider.ts 
// 编译时只放占位标记：
for (const name of secretNames) {
    // The caller replaces this marker with a value in the short-lived
    // Docker argv. It cannot accidentally be persisted as evidence.
    args.push("--env", `${name}=__HARNESS_SECRET_${name}__`);
}

// Provider 在组装 argv 那一刻才替换为真实值：
private withSecretValues(args, environment) {
    return args.map((argument) => argument.replace(
        /__HARNESS_SECRET_([A-Z][A-Z0-9_]*)__/, (_, name) => environment[name] ?? "",
    ));
}

// 错误输出统一脱敏（ENV_NAME=[REDACTED]），截断到 1000 字符：
function redact(value: string): string {
    return value.replace(/(?:[A-Z][A-Z0-9_]{2,})=\S+/g, "$1=[REDACTED]").slice(0, 1_000);
}
白话翻译

编译产物里只有形如 __HARNESS_SECRET_API_KEY__ 的占位符——落库的证据记录即使被拖走也没有真值。

Provider 拿到授权 Secret 后，只在拼 docker argv 的内存瞬间替换占位符。

万一容器报错把环境变量打进 stderr，redact() 会把所有大写形式的 KEY=value 替换成 KEY=[REDACTED]，并截断长度。

三重防线共同保证："证据可以公开审计，密钥不留痕迹"。

声称 ≠ 事实：docker inspect 验证 + 证据三元组

"OCI 兼容镜像不能证明哪个内核/runtime 执行了它。"所以容器创建后还要用 docker inspect 取回实际 runtime 证据——不符就删容器、记 FAILED、抛错：

CODE · src/sandbox/container-sandbox-provider.ts · create 
const verifiedEvidence = await this.adapter.verify(
    this.commands, this.docker, `agent-harness-${input.id}`,
);
if (!verifiedEvidence.verified) {
    await this.commands.run([this.docker, "rm", "--force", `agent-harness-${input.id}`]);
    const reason = verifiedEvidence.verificationReason
        ?? `实际 runtime 不是 ${this.runtime}`;
    const failed = {
        ...record, status: "FAILED" as const, updatedAt: new Date().toISOString(),
        failureReason: reason, runtimeEvidence: freezeRuntimeEvidence(verifiedEvidence),
    };
    this.store.update(failed, "PROVISIONING");
    this.emit(failed, "FAILED", reason);
    throw new Error(`Sandbox runtime 证据校验失败：${reason}`);
}
白话翻译

容器起来了，但"我们要求 runsc"和"实际跑在 runsc 上"是两回事。

验证失败的第一反应不是报警而是清理——先把容器删掉，不留一个弱隔离环境活着。

失败原因写清楚：要么是验证器给出的具体理由，要么是"实际 runtime 与请求不符"。

状态机从 PROVISIONING 推到 FAILED，证据冻结进数据库。

最后向调用方抛错——这次 Run 不会以错误的隔离级别启动。default/restricted-egress profile 甚至在构造函数就禁止 runc 回退；strict 无 KVM 时由 UnavailableStrictSandboxProvider fail-closed。

🔗
证据三元组（Evidence Triple）

intent ──compile──► product ──observe──► fact：policyFingerprint（策略意图指纹）+ specFingerprint（编译产物指纹）+ runtimeEvidence（观测事实）。verifyIsolationTriple 是 fail-closed 的一致性校验：任何一环缺失或冲突 → inconsistent；还支持重编译漂移检测——策略或编译器被偷偷改过就能发现。真机 tripleConsistent=true。

ManagedAgentRuntime：把一切串起来的执行序

归属四元组校验 → computeEffectivePolicy → saveSnapshot → 创建 Attempt → 能力校验 → 策略编译 → Sandbox 创建 → 启动 Runtime → finally 清理。注释原文值得背：

CODE · src/runtime/managed-agent-runtime.ts 
// Attempt 从创建时就绑定不可变策略快照。这样即使能力校验、策略编译或
// Sandbox 创建在真正启动 Runtime 前失败，拒绝记录仍可完整解释。
let attempt = createRunAttempt({
    id: crypto.randomUUID(),
    runId: run.id,
    attemptNumber: this.attempts.nextAttemptNumber(run.id),
    kind,
    instanceId: instance.id,
    templateVersionId: template.id,
    capabilityProfileId: profile.id,
    policySnapshotId: snapshot.id,
    sandboxId: null,
    createdAt: now,
});
this.attempts.create(attempt);
白话翻译

顺序设计的关键：Attempt 先于一切可能失败的步骤诞生，并且出生时就绑定策略快照 ID。哪怕三行之后能力校验失败，审计员也能看到"第 N 次 Attempt 因缺少能力 X 被 REJECTED，依据快照 Y"——拒绝本身是一等公民，也要可解释。

后续链路：validateRuntimeCapabilities 缺强制能力→REJECTED；compilePiPolicy 产出 APPLIED/DEGRADED/REJECTED 全落库；sandbox.create 失败→Attempt FAILED；成功才 startRunAttempt(RUNNING)。finally 里 terminate 容器、Instance 回 READY；onSandboxFailure 订阅保证容器意外 LOST 时 Attempt 转 INTERRUPTED 并发 agent_interrupted 事件。
