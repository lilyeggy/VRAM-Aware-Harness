把一次 Agent 任务，讲透整个仓库。

这不是另一个 Agent Loop，也不是“显存高就排队”的资源过滤器。VRAM-Aware Harness 是一个面向团队的多租户 Agent 任务服务：它把可信 Tenant、受管 Workspace、任务编排、真实 Sandbox、工具副作用、故障恢复和用户结果连接成一条可追踪调用链。

先记住一句话Pi/vLLM 负责 Agent loop 与模型推理；Harness 负责谁能执行、在哪执行、何时执行、失败后能否安全继续，以及用户最终得到什么。

当前状态：控制面与 Workspace MVP 已完成；Linux Docker/runsc、A6000 和 strict microVM 仍需真机证据。

Sandbox 运行时分级

OCI/Docker 是镜像与生命周期接口；runtime 才决定实际执行边界。配置值不等于事实，必须用 inspect/Provider evidence 证明。

Profile实际 Provider能保证什么不能宣称什么
developmentManagedLocal开发/测试生命周期；保留现有 Fake 路径不是真实多租户执行隔离
defaultContainer + runscOCI 参数、非 root、只读 RootFS、网络/PID/资源边界；inspect 必须观察 runsc没有 Linux Docker/runsc 输出前，不能声称真机隔离通过
restricted-egressContainer + runsc当前仍默认无网络尚未接入 egress proxy，不能开放任意公网
strict预留 Kata/Firecracker/托管 microVM Provider路由合同和 fail-closed 行为当前没有自研 VMM，也没有真实 strict Provider

部署与验收课

当前推荐 CPU Linux Server 做控制面/Sandbox 验证；A6000 只在需要真实 vLLM/VRAM admission 时接入。当前容器云实例不能替代完整 Linux VM。

服务器前置

Ubuntu x86_64、root/sudo、rootful Docker、可安装 runsc；需要 Kata/Firecracker 时再确认 /dev/kvm。

外部 Model API

模型不是 Harness 核心。Pi 通过 OpenAI-compatible endpoint 运行；外部 API 没有 vLLM metrics 时不能伪造 VRAM 证据。

真机入口

preflight:server → smoke:container:attacks → benchmark:sandbox。PASS 输出保存原始配置与结果。

# Linux Server deployment gate bun install bun run typecheck bun run test bun run preflight:server # Real Sandbox evidence bun run smoke:container bun run smoke:container:attacks bun run benchmark:sandbox
