03 · common skeleton

名字不同，但骨架高度相似

所有 Harness 都要闭合这条循环。产品间真正的区别，是每个步骤由谁负责、能否恢复，以及边界有多硬。

01 / RECEIVE 接收任务 终端、IDE、消息、API、定时任务或远程客户端
02 / ASSEMBLE 组装上下文 历史、规则、仓库说明、技能、记忆与当前环境
03 / REASON 模型决策 生成回答，或形成对工具、子 Agent 的调用意图
04 / GOVERN 策略裁决 权限、审批、hook、安全规则和隔离边界
05 / ACT 环境执行 文件、shell、浏览器、MCP、容器或远程工作区
06 / OBSERVE 回写与继续 事件、结果、压缩、分支、恢复或下一轮推理
贯穿整条链路 Session / Memory · Event stream · Checkpoint · Telemetry · Cancellation · Retry · Identity
Claude Code上下文层级、权限与 hooks
Hermes记忆、技能学习与多入口
Codex CLI沙箱、审批与 app-server 协议
Gemini CLI工具策略与沙箱扩权
OpenCode主 Agent、子会话与系统 Agent
OpenHands远程工作区与用户级容器

05 · head to head

两两对比：差异不是功能清单，而是责任边界

选择任意两个 Harness，观察它们共同解决什么，以及分别在哪一段建立自己的架构优势。

VS

    共同地基

    它们都必须闭合执行回路

    • 把用户输入与历史、规则、环境组装成模型上下文
    • 把模型的工具意图变成可观测的真实执行
    • 处理工具结果、会话延续、失败和人为介入
    • 在“模型想做什么”和“系统允许什么”之间建立边界

      06 · do not mix layers

      把常见名词放回正确楼层

      Framework 可以成为 Harness 的地基，Temporal 可以让执行持久化，模型可以负责推理；但三者都不自动等于完整 Harness。

      Model / API
      Claude · GPT · Gemini
      提供推理和生成能力，不直接拥有你的 shell、仓库、权限和运行生命周期。
      Runtime / Framework
      OpenAI Agents SDK · LangGraph · Google ADK
      提供构建 loop、graph、handoff、session 的 API；完整产品边界仍由应用开发者决定。
      Agent Harness
      Claude Code · Hermes · Codex · Gemini CLI · OpenCode · OpenHands · Pi
      把模型、工具、上下文、策略、环境和用户入口组装成可以真实工作的 Agent 系统。
      Durable substrate
      Temporal · durable queue · workflow engine
      让长任务可重试、可恢复、可调度；它能承载 Harness，但不会替你定义 Agent 的工具与上下文。
      Product / Fleet
      Tenant · remote workspace · quota · audit · SLO
      管理大量 Harness 实例和用户承诺，是从“单个 Agent 可工作”走向“服务可运营”的一层。

      Architecture takeaway

      优秀 Harness 的核心，不是 loop 更花哨，而是承诺更清楚。

      它必须回答：上下文从哪里来？工具由谁执行？越权时谁阻止？中断后从哪里继续？ 多个 Agent 如何隔离？用户怎样看见过程？这些问题合在一起，才是 Harness 工程。

      学 Hermes记忆—技能—执行构成的持续学习回路
