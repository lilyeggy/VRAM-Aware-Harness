Agent Systems Architecture Atlas

Agent 系统三层全景

从单 Agent 的行为质量，到多个 Agent 的可靠运行，再到模型从交互轨迹中持续学习。 三个项目不是重复造轮子，而是在同一条 Agent 生命周期上分别拥有不同的工程责任。

DeepResearch 决定 Agent 怎样完成任务；Agent 任务服务让团队安全地提交、运行并取得结果； Polar RL Infra 决定模型怎样从执行结果中变得更好。

Two Connected Loops

一条在线链，一条学习链

在线链必须低延迟、可恢复、可审计；学习链必须可复现、可归因、能比较。 它们通过版本化轨迹连接，但不共享内部实现。

        分层评测负责定位问题，端到端评测负责证明整体收益。只看一个总分，会让模型问题、 Agent 策略问题和基础设施问题混在一起。

        E1 / BEHAVIOR

        DeepResearch 质量评测

        回答“Agent 是否真正更会完成任务”。

        • 任务完成率与答案正确性
        • 引用准确率、覆盖率与可追溯性
        • 检索召回、证据利用与幻觉率
        • 规划质量、重复工具调用和失败恢复
        • 相同模型下的 Agent 策略消融
        E2 / CONTROL

        Agent 任务服务评测

        回答“用户能否安全获得结果，多个任务是否被可靠、公平地运行”。

        • Run 成功率、恢复率和事件完整性
        • 队列等待、Tenant 公平性与饥饿
        • 工具幂等、未知副作用和 Checkpoint
        • 吞吐、TTFT、P95 延迟和资源利用率
        • 故障注入与资源过载回退
        E3 / LEARNING

        Polar 训练评测

        回答“训练是否让策略稳定且可复现地变好”。

        • Success rate 与多个随机种子
        • 平均步数、工具数、Token 与延迟
        • Invalid / Repeat / Loop rate
        • Reward、KL、Loss 与训练稳定性
        • WebShop → ALFWorld 泛化证据
        E4 / END TO END

        跨层回归评测

        回答“新模型进入真实 Agent 系统后是否整体更好”。

        • 固定任务集与固定执行预算
        • 旧模型 / 新模型 A/B 对照
        • 质量、成本、延迟的 Pareto 改善
        • 工具协议与安全边界回归
        • 模型版本到轨迹结果的完整归因

        需要理解

          形成的工程能力

            Architecture Rules

            三个项目长期保持独立的原则

            真正的系统性来自清楚的边界和可复现的数据闭环，不来自建立一个包含所有功能的巨型仓库。

            RULE 01

            共享 Schema，不共享 Service

            共享 RuntimeEvent、AgentTrajectory、EvaluationResult 和 ModelVersion；不要跨仓库调用内部 Store 或 Service。

            RULE 02

            每层有自己的真相来源

            Behavior 的真相是任务状态；Control 的真相是 Run 事实；Learning 的真相是版本化 trajectory、配置和 checkpoint。

            RULE 03

            评测必须能定位责任

            模型变差、Agent 策略变差和基础设施过载必须能被不同指标区分，不能只保留一个端到端总分。

            RULE 04

            模型配置不进入业务逻辑

            模型 ID、Template、Parser、量化和上下文长度属于部署配置，三个项目通过 ModelVersion 追踪它们。

            RULE 05

            训练与生产执行解耦

            Polar 可以消费脱敏、版本化轨迹，但不依赖生产 RunService；生产 Control Plane 也不等待训练系统在线。

            RULE 06

            先基线，再跨层优化

            先分别证明 Behavior、Control、Learning 正确，再研究 Agent 语义参与推理调度或真实轨迹驱动模型改进。

            The Complete Agent Discipline

            资深 Agent 专家不必重写所有 Infra，但要理解整个反馈闭环。

            你的主线不是成为 Prompt、分布式系统、RL 和 CUDA 的全能实现者，而是能够判断一个问题属于哪一层、 它需要什么事实、应该由什么契约连接，以及怎样通过评测证明整体真的改善。

            行为层理解模型怎样通过规划、上下文与工具形成可用 Agent。
            控制层理解多个 Agent 怎样在真实资源、故障和多租户环境中可靠运行。
            学习层理解 trajectory、reward 和 rollout 怎样转化为模型策略更新。
            推理底座理解 vLLM 对延迟、吞吐、缓存和并发的影响，但不把 Kernel 作为主线。
            共同语言用版本、事件、轨迹、评测与模型制品连接三个独立项目。
