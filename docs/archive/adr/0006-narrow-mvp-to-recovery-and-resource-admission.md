# ADR 0006：收紧 MVP 到安全恢复与资源感知准入

## 状态

已接受，继续定义 Day 1–7 可靠执行基线；当前产品范围由 ADR 0009 定义

## 背景

Day 1–5 已经建立可替换 Agent Runtime、AgentRun、追加式事件、ToolGateway、
Checkpoint、安全恢复、ResourceObserver 和 ExecutionPolicy。继续实现前需要避免
两个范围漂移：把项目扩张成通用多租户后端平台，或者在没有真实基线的情况下把
Scheduling Agent、KV 管理和深度 vLLM 改造预设为必做方向。

本项目真正能够由现有代码形成闭环、并且区别于普通 Agent SDK 包装器的能力是：

1. 根据已经持久化的工具副作用判断任务能否自动恢复、复用结果或必须停止；
2. 根据自托管推理环境的真实资源状态控制新 Run 的准入与背压；
3. 在故障或资源压力解除后，无需用户重新提交即可继续安全执行；
4. 用事件、Checkpoint、资源快照和策略决定解释系统为什么这样执行。

## 决策

MVP 采用以下规范定义：

> VRAM-Aware Agent Harness 是一个面向资源受限的自托管推理环境、围绕可替换
> Agent Runtime 构建的可靠执行控制面：它持久化 Run 与工具副作用，在安全边界
> 恢复失败任务，并依据实时资源事实控制新执行的准入与背压。

范围按优先级固定为：

1. **核心一：副作用感知的安全恢复。** ToolExecution、Checkpoint、幂等键和
   RecoveryDecision 必须共同决定恢复行为，不能把失败简单等价为从头重跑。
2. **核心二：资源感知的准入与背压。** ResourceSnapshot 必须真实改变
   `START / QUEUE`；状态恢复后队列必须自动推进，不能只展示监控数字。
3. **基础承诺：可审计、可观测。** Run、工具、恢复、资源和策略事实必须能够
   形成一条可查询时间线。
4. **支撑场景：最小多租户。** Tenant 继续贯穿归属、查询和队列公平性，但只用
   两个 Tenant 验证隔离、并发上限和非饥饿，不建设认证、计费或管理后台。
5. **可替换依赖。** Pi 负责 Agent Loop，vLLM 负责 token 级推理和物理 KV；
   Harness 不复制二者的职责。

Day 6 的完成条件不是“有一个 round-robin 类”，而是形成完整的资源队列语义：

- `claimNext` 选中 Run 时同步登记 slot，避免规划与占用分离；
- Run 完成、失败、中断或启动失败时幂等释放 slot；
- 释放 slot 或资源恢复时触发 drain；
- 队列位置、排队原因、准入决策和资源快照可查询；
- 两个 Tenant 的确定性测试证明非饥饿。

Day 7 必须加入真实闭环和对照实验。至少比较“Pi 直接调用 vLLM”和“Pi 经 Harness
调用 vLLM”，记录完成率、过载/超时、P50/P95 延迟、排队时间、资源峰值和重复
工具执行次数。没有真实指标时，只能宣称组件语义成立，不能宣称资源优化有效。

## 非目标

- 通用云厂商 GPU 管理或替代 vLLM Scheduler；
- 生产级多租户 SaaS、认证、RBAC、计费和容器隔离；
- 自研 Agent Loop、Memory 或 Context 管理框架；
- 在没有基线证据时实现 Scheduling Agent、KV 驱逐或 Agent–Inference
  Co-scheduling；
- 对 token 需求作无法校准的强完成保证。

## 后果

好处：

- 保留 Day 1–5 的全部核心实现，不需要重构已有领域模型；
- Day 6 的公平队列成为资源背压闭环的一部分，而不是独立后台功能；
- 项目介绍可以用两个可验证的系统承诺和真实指标展开；
- 后续研究由瓶颈数据选择，减少再次迁移主线的风险。

限制：

- 项目适用场景主要是实验室、on-prem、自托管模型和资源容量明确受限的环境；
- 单进程 SQLite 与内存队列只能证明语义，不能宣称生产级高可用；
- 资源策略收益必须通过真实 vLLM 压测证明，Fake 测试只能证明正确性；
- 多租户能力只达到最小归属和公平性验证，不构成企业平台能力。

## 后续决策门槛

以下门槛继续约束 Agent–Inference 和 vLLM 研究支线。ADR 0009 已将当前主线定义
为多租户 Agent 任务服务，因此必须先完成身份、Workspace、真实 Sandbox 和用户
结果闭环；GPU 对照数据仍是完成证据，不能由更多领域建模替代：

- 排队与公平性问题：持久队列、lease、配额与 SLO；
- 成本预测误差：基于历史 usage 的可校准估计；
- 确定性策略表达不足：Scheduling Agent Shadow Mode；
- vLLM 内部瓶颈：请求归因、priority、KV Events 或更深的调度实验。
