退避重试
tryScheduleRetry：仅当「无任何 PREPARED 副作用」+「非确定性策略拒绝（PolicyRejectionError）」+「retryCount+1 < HARNESS_RUN_MAX_ATTEMPTS」时，把 Run 退回 QUEUED 并写 retryAt = now + min(base·2^(n-1), max)；调度器跳过未到点的 Run
run-service.ts:tryScheduleRetry · run-scheduler.ts:reconcileQueuedRuns
故障观测到的行为为什么不更激进
Worker 进程被杀Master 侧 supervisor 观察到子进程退出 → Attempt FAILED + WORKER_CRASHED；若 Master 观察不到（例如 Master 自身重启），则走租约回收路径 → INTERRUPTED + LEASE_EXPIRED两条路径都保证「不残留 microVM、不丢审计」；有副作用时宁可人工介入
Broker 不可达create 失败 → Attempt FAILED → Run INTERRUPTED(START_FAILED)，无孤儿 sandbox 记录；Broker 恢复后新 Run 正常fail-closed 优于「偷偷在本机跑」
模型服务不可达 / 报错按退避重试到上限后保持 INTERRUPTED；策略拒绝（如 allowNetwork=true）不重试确定性失败重试没有意义，只会放大噪声
宿主出现孤儿 VM / 目录启动对账 + 周期性 reaper 清理；harness-ops.ts cleanup 按年龄/数量清理 vm-runtime 与快照池崩溃后不能靠「人工记得删」

2.1 HTTP 接入层 src/http · 837 行 + routes 856 行

输入
Bun.serve 请求对象 + 客户端 IP（requestIP）
① 全局前置：IP 限流（/health、/ready 白名单）
② 路由分发：按 segments 交给 auth / workspaces / conversations / runs / system / gateway
③ 鉴权：Bearer → principal（tenantId + scopes）→ 租户限流 → 审计 record(ALLOW/DENY)
④ 参数校验：requiredString / optionalNonNegativeInteger / optionalString，非法 → 400 带字段名

⑥ 统一出口：jsonResponse(value, status, headers)；已知错误 → 4xx/429 带 retry-after；未知异常 → 500 + requestId（不再把 SQL 错误文本透给调用方）
输出 / 落库
JSON 响应；access_audit_events（每次访问一条链上记录）；httpRequestCounts（供 /metrics）
设计要点 租户身份只来自凭据，不来自请求体；限流分 IP / 租户两级且租户桶在鉴权成功后才计（否则一个攻击者能用别人的 tenantId 打满对方的桶）；错误分层（400 参数、403 策略、404 租户边界、409 冲突、429 限流/背压、500 内部）让前端能精确处理。

RunScheduler：执行编排

输出

真实缺陷与修复 最早的实现里 drainOnce 会等本批 Run 全部结束才处理下一批 —— 端到端 smoke 里「并发提交两个 Run」实际是串行。修复是让 submit/resume 之后走 kick() 独立抢 slot，同时给调度器加 isActive/isQueued 让 reconcile 跳过已 claim 的 Run（否则会抛「Run 正在执行中」）。

3.7 面试追问：我踩过的坑与设计取舍

Q1. 为什么 Broker 要 root，而 Master 不要？ 最小特权原则：需要 /dev/kvm、jailer chroot、cgroup 写入的只有 Broker。Master 承担鉴权、调度、DB、模型编排，把它做成非 root 后，即使 Master 被攻破也拿不到 KVM/设备权限；Broker 只暴露 create/execute/terminate 三个操作，且用 controlToken + SO_PEERCRED + capability token 三重校验。代价是部署复杂一点（两个 unit、一个 socket、sudoers 只放行 worker launcher），换来权限域清晰。
Q2. 快照加速很香，为什么还要 fail-closed？ Firecracker 的 /snapshot/load 不支持覆盖 block device 路径，快照里固化的是黄金 VM 的宿主绝对路径。非 jailer 模式下每 Run 的磁盘路径不同，恢复出来的多台 VM 会指向同一块 workspace 磁盘 —— 跨租户串写、产物导出为空。jailer 之所以安全，是因为 chroot + mount namespace 里路径固定为 /workspace.ext4。所以驱动构造函数里直接拒绝「非 jailer + 快照」这个组合，而不是靠文档提醒。
Q3. 为什么 UNKNOWN_EFFECT 绝不自动重放？ 重放的代价不对称：READ_ONLY 重跑最多浪费一次读；bash 或未声明效果的 MCP 工具重跑可能重复下单、重复写文件、重复扣款。所以自动重放的门槛是「PREPARED + READ_ONLY」，其余一律人工复核（resolve-unknown-effect 给一个显式出口）。这是 fail-closed 的典型应用：不确定时选更保守的那个。
Q4. 限流为什么分 IP 和租户两级？ 只用 IP：一个 NAT 后的实验室所有人在同一桶里互相挤。只用租户：未鉴权的请求没有租户，攻击者可以无限打鉴权接口。所以 IP 桶在鉴权前（保护登录/注册/探测），租户桶在鉴权成功后（保护配额公平）。租户桶必须在 principal 解析之后计，否则伪造 body.tenantId 就能打满别人的桶。
Q5. 调度器为什么要有 kick 和 drain 两套？ drain 是「批量推进 + 等本批结束」，适合周期补偿；但如果新提交的 Run 只能等下一批，用户体验就是「并发提交实际串行」（我们在 p0 smoke 里真的观察到了）。kick 只起一个 attempt 且不 await，让新 Run 立刻抢 slot，同时保留 drain 的批次语义与单飞保护。reconcile 还要跳过已 claim 的 Run，否则会抛「Run 正在执行中」。
Q6. 工具为什么要「先记账后执行」？ 如果先执行后记账，进程在两者之间崩溃就会留下「做过的副作用没人知道」的黑洞，恢复时无法判断该不该重跑。先写 PREPARED 后执行，崩溃后至少知道「有个效果不明的执行」；配合 canAutomaticallyReplay，安全的重放，不安全的转人工。
Q7. 单机 SQLite 会不会成为瓶颈？ 对 10-20 人实验室规模够用：WAL + busy_timeout=5000 让读写并发不互相阻塞，写路径都在单个 Master 进程内（无多写者竞争）。真正的瓶颈更可能是模型服务往返和 VM 创建（冷启动 1.5s / 恢复 0.5s）。要上多机，第一步是把「Run 事实 + 租约」换成带 lease/heartbeat 的共享存储，再引入按租户的 Worker 池。
Q8. 怎么证明隔离真的生效，而不是「看起来隔离」？ 三层证据：① 代码层能力声明（SandboxEnforcementCapabilities），工具策略守卫据此 fail-closed；② 对抗脚本（多 VM 并发 + 跨租户 marker/secret/文件可见性 + 残留进程与目录检查）；③ 真实事件与宿主观测（ss 看 guest 无网卡只有 vsock、pgrep 看进程数与归属、unit 属性看 cgroup/seccomp/Landlock 是否真的应用）。还踩过一个「假隔离」：provider=microvm 但没显式指定 driver 时会静默退到 Mock，事件里的 runtime 字段只是策略值 —— 这也是为什么我把 warmHit 做成如实回传、把能力声明做成显式数据。
Q9. 最难定位的一个真实 bug？ 真机上任务「卡在 RUNNING」：宿主 curl https://opencode.ai 返回 200，但 Worker 里模型调用一直不动。取证链：worker 进程的 ss 显示对 Cloudflare IPv4 全部 SYN-SENT；curl -4 超时、curl -6 成功 → 宿主 IPv4 出站到该网段黑洞；而 Worker 因为之前修「IPv6 被 IPAddressDeny 丢弃」把 RestrictAddressFamilies 钉死成 AF_INET，于是永远走不通。修复是恢复双栈 + 显式 IPv6 前缀白名单 + 临时 /etc/hosts pin；同时暴露出「模型调用没有超时」这个更深的问题（心跳还在续租，reaper 不会回收）。
Q10. 如果继续做，你会先改什么？ ① 模型调用超时与失败快速降级（避免心跳掩盖挂起）；② 快照门控后复查（并发冷启动时复用首个完成的快照，warmHit 从 0 变 N）；③ 把审计链扩展到 tool_executions 与模型调用 payload；④ Worker 侧的模型凭据换成短期令牌；⑤ 只有到那时才考虑多机与 HA。
