运行时映射：一个 HarnessSession 在同一时刻通常关联一个活跃的 piSessionRef；多个 AgentRun 按顺序使用该 PiAgentSession 的历史上下文。AgentRun 不保存整段消息历史，只保存自己的输入、状态、事件和恢复信息。
场景 01 · 首次任务

先创建 Run，再决定是否执行

用户输入属于 HarnessSession；RunService 为这一次输入创建 AgentRun。ExecutionPolicy 基于 ResourceObserver 决定是否启动；MVP 使用确定性规则，未来允许 Scheduling Agent 在硬约束内提出建议。通过准入后，PiAdapter 创建或打开 PiAgentSession，再调用 prompt。

业务身份：HarnessSession执行单位：AgentRun历史上下文：PiAgentSession
最重要的纠偏：HarnessSession 不负责观察 GPU、排队或恢复；它只是这些服务共同使用的稳定业务上下文。真正调度的是服务层，真正执行的是 Agent 层，真正消耗资源的是基础设施层。Scheduling Agent 即使以后加入，也只在服务层的 Hard Guardrails 内提供建议，不能绕过安全边界。
