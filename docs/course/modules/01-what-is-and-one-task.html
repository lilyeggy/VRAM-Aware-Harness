这是什么？一次任务的一生

这不是另一个「会聊天的 AI」——它是一层控制面：决定谁能跑、在哪跑、何时跑、失败后怎么办，最后把回答 + Diff + Artifact 交给你。

这不是 AI，是一家「代办事委托中介」

想象你走进一家代办事委托中介：你把任务交给柜台，它替你把一切都安排妥当。

🧾

登记台

接收你的任务，先验明正身（密钥），再登记入册。

🗓️

派单调度

看资源够不够，安排谁先上、谁排队。

📦

隔离工作间

每个任务一间独立隔离的房间，谁也不能串门。

📒

记账本

每一步动作都落账，最后给你一张可查的审计收据。

办完后，中介把结果和收据一起还给你。模型负责动脑，这套系统负责「中介与安保」。

🏗️
一个系统，三层分工

控制面（Control）管「谁能跑、在哪跑、何时跑、失败了怎么办」；行为（Behavior）由模型负责——它动脑；基础设施（Infrastructure）提供隔离工作间与算力。三层各司其职，互不越界。

你提交一次任务

你喊一嗓子——本质上只是一次HTTP 请求，只需要给两样东西：一个 workspaceId 和一段话。

🔑
密钥

密钥放在请求头里，身份不用你自报。

📇
workspaceId

告诉系统：这次任务在哪间办公室干活。

💬
userInput

要办的事，就一段话——你说人话，它听得懂。

身份验证不过关，服务器就直接回你一个 401。来看看真实代码里，这个「验明正身」的动作长什么样：

CODE 
        const authorization = request.headers.get("authorization");
        const rawKey = authorization?.startsWith("Bearer ")
            ? authorization.slice("Bearer ".length).trim()
            : request.headers.get("x-api-key")?.trim();
        if (rawKey === undefined || rawKey.length === 0) {
            this.audit("AUTHENTICATE", "DENY", null, "missing_api_key");
            throw new HttpError(401, "缺少 API Key");
        }
        const principal = this.accessControl.authenticate(rawKey);
PLAIN ENGLISH

先从请求头的 authorization 栏里，取出那一串凭证。

如果它以 Bearer 开头，就剪掉前缀只留暗号；否则试试另一个叫 x-api-key 的栏位——两种常见的「递暗号」方式都认。

如果什么都没拿到，先在账本上记一笔「鉴权被拒」……

……然后抛出一个 401：HTTP 界的「你没有通行证」。

把密钥交给认证器核对，换回一张代表「你是谁」的身份卡（principal）。

💡
任务状态 ≠ 事件历史

「现在是什么」和「发生过什么」是两套记录：状态只存当前这一个点；事件则是一条条带时间戳的完整轨迹。出问题时，永远先问「发生过什么」。

在隔离工作间里执行

每个任务都在独立的 Sandbox（容器，默认 gVisor/runsc）里执行。

它只能看到自己的 Workspace，默认不能上外网，也碰不到别人的文件。

独立容器 每个任务一间小电脑，互不串门
只挂载自己的 Workspace 桌上只有自己的文件
默认断网 不能偷偷往外发数据

每个动作都被记账

工具调用会产生副作用，所以系统先记「准备执行」，再执行，再存结果——像开一张带复写联的收据。

1
记录「准备执行」

AI 说要调 write 了，账本先落一笔。

2
真正执行

工具动手，文件被改写。

3
存下结果与审计

结果归档，收据入账，事后随时可查。

真实代码里，「开收据」就是往审计账本里 record 一条：

CODE 
        this.accessControl?.auditStore?.record({
            action, outcome,
            subjectId: principal?.subjectId ?? null,
            tenantId: principal?.tenantId ?? null,
            resourceType: "HTTP_REQUEST",
            resourceId: null,
            reason,
        });
PLAIN ENGLISH

往审计账本里记一条。

谁（subjectId）、哪个租户（tenantId）、什么动作、结果如何。

资源类型是 HTTP_REQUEST，编号为空，再附上原因。

一笔收据就此入账，事后随时可查。
